# 架构说明

## 文件

| 文件 | 职责 |
|---|---|
| `okx_openapi_client.py` | OKX 官方签名与请求客户端，原样拷贝，不修改 |
| `guard.py` | 配置、凭证、护栏、下单、对账、体检报告 |
| `cli.py` | 命令行入口 |
| `test_guard.py` | 离线测试，用 `FakeOKX` 模拟交易所 |

## 下单流程（`guard.submit`）

1. **校验 Builder Code**：缺失或格式不对，在发出任何请求前就报错。
2. **加文件锁**：同一时间只允许一个进程下单。
3. **前置检查**：读账户配置，`acctLv` 必须是 1 或 2（cash 模式）；读品种规则（`lotSz`、`minSz`、状态）和最新价。
4. **计算数量**：市价买按计价币金额（`tgtCcy=quote_ccy`）；卖出和限价按基础币数量，向下取整到 `lotSz`。名义金额低于约 1 USDT 时拒绝。
5. **幂等检查**：由意图和 `--intent-id` 算出固定的 `clOrdId`，先查询；已存在则跳过。本地日志显示曾提交但查询不到时，拒绝重下，要求人工核对。
6. **护栏检查**：HALT、白名单、订单类型、单笔上限、每日笔数、每日买入额、同品种冷却。已提交和结果未知的订单都计入额度，被交易所拒绝的不计入。
7. **下单**：通过官方客户端发送，`tag` 为 Builder Code。网络异常记为 `submit_unknown`。
8. **回查**：按 `clOrdId` 轮询订单状态，记录成交量、均价、手续费，并核对 `tag`。

## 审计日志状态

| status | 含义 | 计入额度 |
|---|---|---|
| `blocked` | 被护栏拒绝 | 否 |
| `rejected` | 交易所拒绝 | 否 |
| `submit_unknown` | 网络异常，结果未知 | 是 |
| `submitted` | 交易所已接受 | 是 |
| `reconciled` | 回查结果 | — |
| `duplicate_skipped` | 同一意图已存在，未重复下单 | — |

## 体检报告（`guard.analyze`）

- 数据来自 `GET /api/v5/trade/fills-history`（近 3 个月），每页 100 条，按 `billId` 翻页，每页间隔 0.25 秒以符合限频。
- 手续费字段为负表示付费；以基础币扣的手续费按成交价换算成计价币。
- 只统计 USDT/USDC 计价的交易对，其余计数后跳过。
